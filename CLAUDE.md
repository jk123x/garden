# Garden Catalogue

Personal garden care app for tracking plants and seasonal tasks. Melbourne, Zone 10b.

**What this project is for (Jay, July 2026):** quick-reference guides. Jay grabs spare moments in the garden and wants to glance at a page and instantly know the next task and how to do it. Every page, card and nextAction should be written for that glance — task first, instructions inline, no context-hunting. Seamless is the bar.

## Dashboard rules

- The dashboard "To do" section is **data-driven** — pulled from plants with `urgency` set, displaying `nextAction`. Do not add hardcoded HTML lists to `index.astro`. To add a to-do item, edit the relevant plant YAML.
- **The organising principle is actionability, not importance** (Jay, 21 Aug 2026): the box answers "what can I do right now with spare garden time." Three states: **Do now** (actionable today), **Waiting** (date-blocked — can't be done yet), **Whenever you're passing** (doable any time, low priority — the `later` tier).
- **Date windows:** optional `readyFrom` / `dueBy` (YYYY-MM-DD) on the plant. An urgency item with a future `readyFrom` renders in the muted "Waiting" list with a "from 25 Aug" chip and **auto-promotes into "Do now" on that date — client-side JS in index.astro re-sorts against the real current date on every page load**, so no manual re-tagging and no stale build-time splits. `dueBy` shows a "by 27 Aug" chip that flips red ("was due") once passed. Any date-gated task (spray windows, treatment intervals, "check in early Sept") should get `readyFrom` + `urgency: today/week` — do NOT park date-gated work in `later`, and do NOT write dates only into nextAction prose.
- **nextAction contains ONLY the immediate job** (Jay, 5 Sept 2026: "why put aerate on my to do list if it's not til october? our whole thing is using the calendar"). Future work never rides along as prose in a do-now card. Route by horizon: month-anchored work → monthly `tasks` (the calendar); date-gated work within a few weeks → `readyFrom`/`dueBy`; recurring regimes (e.g. 6-weekly shears) → `tasks` with the right months, not a sentence in nextAction.
- Urgency tiers within "Do now": `today` and `week` for imminent work, `ongoing` for continuous-but-important things (e.g. Feijoa fruit pickup — fruit fly garden health). `later` is for genuinely un-dated low-priority stuff (lavender trim, winter grass spot-pulling) — renders as "Whenever you're passing" below the monthly tasks. If the work is already captured in the monthly tasks list, don't duplicate it as urgency — EXCEPT when telling Jay in chat "do this now": anything recommended as do-now must also get `urgency` + `nextAction` so it shows in the To do box (Jay, 5 Sept 2026). Monthly-task presence alone isn't surfacing.
- **Conditional tasks must state their trigger** (Jay, 5 Sept 2026): never write "divide if overcrowded" / "repot if rootbound" style tasks without the concrete tell. Write the signal into the task text (e.g. "dead centre with growth only round the rim = divide") so the check takes 10 seconds and doesn't outsource the judgment. ## Watering and irrigation

The garden runs **garden-wide drip irrigation** that's switched off through autumn and winter (rain handles it) and back on for spring/summer. Do NOT add per-plant "reduce watering", "less water in winter", or "minimal watering" tasks — they're noise. Watering at the system level is Jay's call, not a per-plant decision.

Per-plant watering tasks should only exist for: (a) new plantings before they're hooked into drip, (b) plants with genuinely different water needs (succulents, drought-natives in pots), or (c) deep-watering during specific heat events.

## Logging field work

Plant YAMLs have a `log` field — array of `{ date, entry, category? }`. Use it for dated, one-off observations and work (weeding, pest sightings, repairs, infestations). Distinct from `tasks` (recurring monthly template) and `notes` (durable description). When Jay reports field work, append to the relevant plant's `log`, update `lastAssessed`, and refresh the `health` line if the state changed.
